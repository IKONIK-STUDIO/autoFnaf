# FNAF Automation Bot (Python)

## ⚠️ Disclaimer

This project is **under active development** and should be considered a prototype. The code is currently unstable and contains multiple temporary / experimental implementations.

The goal is to build a modular system where each *FNAF title has its own dedicated Python script* (e.g. FNAF 1, FNAF 2, etc.). At the moment, only **FNAF 1 basic keyboard control** is implemented.

---

## 📌 Project Goal

This script is an automation / semi-automation control system for FNAF games that:

* simulates mouse movement and clicks
* reacts to keyboard input
* handles multi-monitor coordinate scaling using percentage-based mapping
* will later support pixel-based decision making (WIP)

---

## 🧰 Requirements

The project requires Python 3.10+.

### Required libraries:

```bash
pip install pyautogui
pip install keyboard
pip install mss
pip install screeninfo
```

### Used modules:

* `pyautogui` – mouse movement and clicking
* `keyboard` – keyboard input detection
* `mss` – fast screen pixel capture
* `screeninfo` – monitor resolution and position handling

---

## 🚀 Running the script

```bash
python main.py
```

After launching:

1. Available monitors are listed
2. You select which monitor the game runs on
3. The main loop starts

## 🎮 Controls (FNAF 1)

### Core gameplay controls

* **Q** → Left door (toggle)
* **A** → Left light
* **W** → Right door (toggle)
* **S** → Right light
* **E** → Camera system toggle (automated click sequence)

---

## 🧪 Debug / Development controls

These are strictly for development and testing:

* **C** → Prints RGB color of the pixel under the cursor
* **X** → Prints current cursor position in monitor percentage coordinates

---

## ⚙️ How it works

The system:

* converts absolute monitor coordinates into percentage-based values
* converts them back into absolute positions when needed
* moves the mouse accordingly
* performs simulated clicks

This approach is intended to provide compatibility across different screen resolutions (theoretical stability).

* Pixel-based detection is not fully implemented yet
* Timing (`sleep`) values are still being tuned

In short: **this is a development-stage automation project, not a finished tool**.
